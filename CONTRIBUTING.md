# Contributing

Thanks for considering a contribution. This document covers the legal terms
under which contributions are accepted.

## License of contributions (inbound = outbound)

This project is licensed under AGPL-3.0-only. See [LICENSE](LICENSE) for the
full license text.

Contributions you submit are accepted under the same license that already
applies to the file(s) you change - "inbound = outbound". You retain
copyright on your contribution; you grant the project and its users a
license to use your contribution under the file's declared license.

## Developer Certificate of Origin (DCO)

This project uses the [Developer Certificate of Origin](https://developercertificate.org/)
(DCO) to confirm that you have the right to submit each contribution under
the terms above. The DCO is a lightweight per-commit attestation - there is
no separate form to sign.

Every commit must include a `Signed-off-by` trailer matching the author of
the commit:

```
Signed-off-by: Your Name <your.email@example.com>
```

Add it automatically with `git commit -s`. The full text of the DCO is at
<https://developercertificate.org/> - submitting a signed-off commit is your
statement that the DCO applies to that commit.

## Commit messages

Commit messages must follow
[Conventional Commits](https://www.conventionalcommits.org/). Release tooling
uses those prefixes to decide version bumps and changelog entries.

## Possible future CLA

The maintainers reserve the right to introduce a Contributor License
Agreement (CLA) at a later point - for example, to support a dual-licensing
offering (see [COMMERCIAL.md](COMMERCIAL.md)). If that happens, contributors
will be notified, and the CLA will apply to contributions made after the
cutover; it will not be retroactively imposed on contributions already
accepted under DCO.

## Getting started

Open an issue or draft PR early for non-trivial changes - alignment before
code is cheaper than alignment after code.
